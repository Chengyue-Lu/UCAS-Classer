# v1.1.x -> v1.3.0 路线

更新时间：2026-09-05

## 当前判断

`1.2.0` 已把自动更新、版本提醒、仓库入口和发布 manifest 生成链路接入；`1.2.1` 完成新版 SEP 首次登录桥接与静默更新安装验证；`1.2.2` 收口持久化登录环境、窗口侧收稳定性与界面细节。
后续 `1.2.x` 更适合围绕自动更新真实发布链路、登录态稳定性、未读红点和作业详情体验做小步修复，`1.3.0` 再承接课表与待办整合。

## 1.1.x 维护重点

### 1. 作业详情作为主线

- 继续清洗详情正文，压掉课程平台里杂乱的 HTML 与空结构
- 处理图片、附件、复杂正文的可读性
- 保证作业列表状态、详情状态、详情 URL 三者一致
- 继续验证缓存命中与重抓时机，让详情链表现更稳定
- `1.1.2` 已完成已提交且已截止作业详情入口修复：详情链会用 `workId / workAnswerId` 回到当前列表，优先选择可访问的“查看”URL，并同步更新前端“打开作业入口”
- `1.1.2` 已把作业提醒去重从易变化的 `workUrl` 推向稳定身份，状态变化不应再误报为新作业
- 下一步仍建议集中在图片、附件真实下载链接覆盖率、长正文阅读体验，而不是扩展作业提交能力

### 2. 登录态与运行时稳定性

- 继续观察 `check -> interrupt -> recovery` 这条链
- 优先区分“cookie 失效”和“临时离线 / 校园网切换 / DNS 异常”
- 保持“失败不急于删除旧登录态”的原则
- 继续复核后台 cookie refresh 的真实效果和触发时机

### 3. 提醒与采集可信度

- 继续验证 `summary -> full` 升级是否足够敏感且不过度
- 继续观察通知 / 资料 / 作业提醒是否有重复、漏报或误报
- 如果后续加日志，也应优先加在调度和提醒边界，而不是 UI 表面

### 4. 打包与安装体验

- 继续保证主仓与 package 的同步边界清楚
- 保持 fresh install 的默认路径、资源准备、版本号更新流程稳定
- 每次修 runtime 都要顺手复核 package 行为，不把 package 当“自动跟上”

## 1.2.0 发布基线

### 1. auth / runtime 韧性更强

- 让 interrupt 恢复逻辑对真实网络波动更温和
- 减少“需要人工重新登录，但其实只是临时断网”的误判
- 让手动 `check`、后台 `check`、cookie refresh 的职责更清楚

### 2. 作业详情体验更完整

- 在 `1.1.x` 已打通的基础上，把详情展示真正做顺
- 处理图片、附件、多段正文、长内容阅读体验
- 让“列表摘要 -> 详情打开 -> 本地缓存”这条链更可解释

### 3. 应用自动检测更新

- 已接入 Tauri 官方 updater
- 更新源使用 GitHub Release `latest.json`
- 支持启动时自动检查新版本
- 支持设置页手动检查更新
- 检测到新版本后弹窗，用户确认后下载并安装
- `1.2.0` 之前用户仍需手动安装一次 `1.2.0`；从 `1.2.0` 起后续版本可自动更新

### 4. 发布与维护流程更顺

- 文档、同步、打包、版本号更新的流程再压平一轮
- 让“主仓修复 -> package 同步 -> 打包验证”更像固定流水线
- 把阶段文档及时归档，避免交接入口再次变旧
- package 侧新增 `npm run release:manifest`，用于生成 GitHub Release 需要的 `latest.json`
- updater 私钥必须保存在本机或安全环境变量，不进入仓库

## 1.2.1 修复基线

- 首次或新浏览器登录落到新版 SEP 工作台后，自动补走官方“国科大在线” SSO 入口并建立 MOOC 会话
- 验证码和设备验证继续由用户人工完成，不扩大自动化登录范围
- 用户确认更新后采用当前用户级静默安装，并在安装完成后自动重启
- 已用独立测试应用完成 `1.2.0 -> 1.2.1` 的本机签名、下载、安装和重启链路验证

## 1.2.2 修复基线

- 登录使用专用持久化浏览器环境，应用只保存并自动填充 SEP 用户名
- 窗口侧收加入转换互斥、严格尺寸边界和更平滑的过渡状态
- 课程统计、作业进度、模块空状态和文件夹选择取消体验完成细节收口

## 1.3.0 重要功能方向

### 1. 课表整合进主程序

- 把课表作为正式模块组合进现有课程体系
- 让用户能在同一应用里看到课程列表、课表视图和课程相关内容
- 课表数据源和更新策略应尽量复用现有采集与本地存储能力

### 2. 以课表为中心组织待办

- 围绕课表时间轴整合作业、提醒、个人待办
- 让“课程 -> 时间 -> 待办事项”形成更自然的组织方式
- 优先做和课程强相关的待办，不急着扩成泛用效率工具

### 3. 日常使用入口更统一

- 让 dashboard、课程详情、课表、提醒之间的跳转更顺
- 把用户高频动作尽量收敛到少数几个稳定入口
- 避免课表功能成为孤立新页面，而是作为主线信息组织升级

## 暂不建议在 1.2.0 / 1.3.0 做重投入的方向

- 作业代提交
- 大范围 UI 重做
- 再起一轮架构级重构
- 与核心“课程 / 课表 / 资料 / 通知 / 作业 / 提醒”无关的外围功能扩张

## 一个简化判断

如果只用一句话概括：  
`1.2.x` 负责把自动更新、作业详情和稳定性继续做扎实，`1.3.0` 再把课表和待办整合成真正的新主线。
